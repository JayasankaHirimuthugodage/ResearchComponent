# Cognitive TabICLv2 finalization infrastructure

This is a post-hoc, development-only experimental workflow. It uses only the frozen 500-person development partition, 16 baseline inputs, the approved local checkpoint, and the shared 5x5 folds. It never loads the 125-person cohort.

Nested outer folds estimate performance: each outer-training partition creates three inner OOF probability sets, fits a sigmoid calibrator, and selects a Youden-J threshold. Those fold thresholds are evaluation-only. For a separately approved final prototype, five repeat-level raw OOF probability vectors are averaged, one final sigmoid calibrator is fitted on that development OOF vector, and one final Youden-J threshold is selected. This reuses development evidence and is selection-optimistic; it is not independent validation or a clinical threshold.

The future release manifest must be an experimental Cognitive-only artifact and record checkpoint/package hashes, seeds, split/fold fingerprints, feature contract, calibration coefficients, threshold, and limitations. It must contain no participant identifiers, raw records, or row-level predictions. The 500-person labelled context must be reconstructed locally from the checksum-verified development partition at inference time; it must not be copied into the release.

Each future release directory also uses a detached SHA-256 integrity index. The index names the aggregate report and release manifest with repository-relative paths and hashes, but never hashes itself, avoiding a circular dependency. Verification requires every indexed artifact to exist beneath the repository root and match its recorded hash; a missing, changed, or partial artifact fails closed. A locally stored index detects accidental alteration, but is not a signature or protection against an attacker able to alter both the artifact and index.

Reconstruction inputs are the authorized local dataset, split manifest, split summary, approved checkpoint and package version. The loader must verify dataset/split fingerprints, feature schema, target identity and checkpoint hash before reconstructing the context in memory. Missing, altered, unauthorized, or incomplete inputs must fail closed. This is sufficient for an experimental development finalization run; it is not sufficient for application activation. Application-level authorization, local data-access controls, lifecycle management and runtime integration are Phase 3 blockers.
